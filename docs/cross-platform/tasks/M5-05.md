# M5-05 — Wire P2P sync into the Android, iOS and desktop apps

GitHub issue: #12. Spec: `docs/p2p-sync/PLAN.md` § "When sync runs" (foreground: start server + sync all peers; 5 s debounce after a local change while in the foreground; Android WorkManager periodic 15 min on unmetered network that briefly runs server + client; manual "Sync now"). Building blocks (all in `shared/src/commonMain/kotlin/com/yogeshpaliyal/deepr/p2p/`): `node/P2pNode`, `http/P2pServer`, `http/KtorHttpPost`, `http/localIpv4Addresses()`, `node/SecretStore`; platform pieces: `JvmP2pCrypto` (jvmShared), `ios/CryptoKitP2pCrypto` (iosMain), `KeystoreSecretStore` (androidMain), `KeychainSecretStore` (iosMain), `FileKeySecretStore` (jvmMain). No UI in this task (M5-06), no protocol changes.

## Part A — common controller, `shared/src/commonMain/kotlin/com/yogeshpaliyal/deepr/p2p/P2pSyncController.kt`
`class P2pSyncController(db: DeeprDB, val node: P2pNode, private val server: P2pServer, private val scope: CoroutineScope)`:
- `val running: StateFlow<Boolean>`, `val port: Int?`.
- `suspend fun start()`: start the server on **preferred port 47321** (stable across restarts, because joiners store the inviter's host:port), falling back to port 0 if it's taken; then `syncAll()` in `scope`. `suspend fun stop()`. Both idempotent.
- `fun onForeground()` / `fun onBackground()`: start if this device has peers **or** an active invite (don't open a listening port for nothing); stop on background.
- Debounced sync after local edits: observe `SELECT MAX(seq) FROM SyncMeta` (new query `maxSyncSeq`) with SQLDelight `asFlow().mapToOneOrNull()` (`coroutines-extensions` is already an `api` dep of `:shared`); while running, after a change wait **5 s** (`debounce`) then `node.syncAll()`. Remote applies also bump `seq`: that's fine (mesh forwarding is the spec), but don't loop faster than the debounce.
- `suspend fun syncNow(peerId: String? = null)` for the UI (one peer or all).
- `fun inviteHosts(): List<String> = localIpv4Addresses()` and `fun startInvite(profileId: Long): String` = ensure started, then `node.startInvite(profileId, inviteHosts(), port!!)`.
- Default device name: if `SyncDevice.deviceName` is blank, set it from an `expect fun defaultDeviceName(): String` (Android `Build.MANUFACTURER + " " + Build.MODEL`; desktop `InetAddress.getLocalHost().hostName` or `System.getProperty("user.name") + "'s computer"`; iOS `UIDevice.currentDevice.name`).
- Tests (`shared/src/jvmTest/.../p2p/P2pSyncControllerTest.kt`, two nodes on loopback like `P2pHttpLoopbackTest`): `start()` binds 47321 or a fallback; `onForeground()` with no peers and no invite doesn't start; a local insert on the joiner triggers a sync within ~6 s (use a short debounce via a constructor parameter); `stop()` frees the port.

## Part B — Koin
`shared/src/commonMain/.../di/P2pModule.kt`: `fun p2pModule(crypto: P2pCrypto, secrets: SecretStore) = module { single { P2pNode(get(), crypto, secrets, KtorHttpPost(), clock) }; single { P2pServer(get()) }; single { P2pSyncController(get(), get(), get(), CoroutineScope(SupervisorJob() + Dispatchers.Default)) } }` (clock = epoch ms). Each app adds it to `startKoin`.

## Part C — Android (`app`)
- `DeeprApplication`: `modules(sharedModule, appModule, p2pModule(JvmP2pCrypto(), KeystoreSecretStore()))`; in the existing `ProcessLifecycleOwner` observer add `onStart` → `controller.onForeground()` and `onStop` → `controller.onBackground()` (keep the existing AppLock line).
- `app/src/main/java/com/yogeshpaliyal/deepr/sync/P2pSyncWorker.kt`: `CoroutineWorker` that, only if the app is not in the foreground, runs `controller.start()`, `node.syncAll()`, `controller.stop()`. Schedule a unique periodic work (`P2P_SYNC`, 15 min, `NetworkType.UNMETERED`, `ExistingPeriodicWorkPolicy.KEEP`) in `onCreate`, following `GoogleDriveAutoBackupWorker`'s style.
- Manifest: `INTERNET` (check it's there), `ACCESS_NETWORK_STATE` if WorkManager constraints need it.

## Part D — desktop (`desktopApp/.../Main.kt`)
`startKoin { modules(sharedModule, desktopModule(dir), unsupportedFeaturesModule("desktop"), p2pModule(JvmP2pCrypto(), FileKeySecretStore(File(dir, "p2p-secret.key"), JvmP2pCrypto()))) }`; call `onForeground()` after start and `runBlocking { stop() }` in `onCloseRequest` before `exitApplication`.

## Part E — iOS
- `ui/src/iosMain/.../MainViewController.kt` `initKoin`: add `p2pModule(CryptoKitP2pCrypto(), KeychainSecretStore(CryptoKitP2pCrypto()))`. Observe `UIApplicationDidBecomeActiveNotification` → `onForeground()`, `UIApplicationDidEnterBackgroundNotification` → `onBackground()` via `NSNotificationCenter.defaultCenter.addObserverForName(..., queue = null) { … }`.
- The Share Extension (`ShareExtension.kt`) must **not** start sync: give `initKoin` a parameter `withP2p: Boolean = true` and pass false from `saveSharedLink`.
- `iosApp/project.yml` app target Info.plist properties: `NSLocalNetworkUsageDescription: "Deepr syncs your links with your other devices on the same Wi-Fi network."` (required by iOS 14+ for LAN connections).

## Review
### Review (orchestrator, 2026-11-06)
Structure follows the brief. Orchestrator fixes: (1) `start()` leaked a new change-watcher on every start (never cancelled) ⇒ after a few foreground/background cycles one edit triggered several syncs; now one `watcher` Job cancelled in `stop()`. (2) `start()` ran the initial `syncAll()` inline, so `startInvite` waited for every unreachable peer to time out before showing the code ⇒ launched in `scope`. (3) `running` was set before the bind ⇒ set after. (4) Koin clock used `epochSeconds * 1000` ⇒ `toEpochMilliseconds()`. (5) Android worker: `PeriodicWorkRequestBuilder<…>().setInterval` doesn't exist ⇒ constructor interval; skip when no peers; `stop()` in `finally`; no double sync. (6) iOS: `platform.Unsupported.NSNotificationCenter` ⇒ `platform.Foundation`, and `addObserverForName` needs `object = null`. No dedicated test for (1) (would need a sync-counting harness); local checks green; Android/iOS compile is CI's.
