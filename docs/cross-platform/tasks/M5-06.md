# M5-06 — Sync UI (once, in `:ui` commonMain): share a profile, join, sync settings

GitHub issue: #12. **Spec: `docs/p2p-sync/PLAN.md` § "Sync UI spec (for P5)" — follow it.** Backend (done, don't change behaviour): `shared/src/commonMain/kotlin/com/yogeshpaliyal/deepr/p2p/P2pSyncController.kt` (`startInvite`, `syncNow`, `node`, `running`), `p2p/node/P2pNode.kt` (`pendingPairing`, `confirmPairing`, `rejectPairing`, `cancelInvite`, `join`, `completeJoin`, `unshare`, `removePeer`, `removeAllPeers`, `setDeviceName`), `p2p/core/Pairing.kt` (`decodeInvite` for the invite's profile name and expiry), queries in `Deepr.sq` (`getAllPeers`, `getPeerShares`, `setMaxPeers`, …). Koin: `shared/.../di/P2pModule.kt`.

## Part A — `SyncViewModel` (`shared/src/commonMain/kotlin/com/yogeshpaliyal/deepr/viewmodel/SyncViewModel.kt`, same style as `AccountViewModel`; register with `viewModelOf` in `p2pModule`)
State as `StateFlow`s: `peers` (each: id, name, shared profile names, lastSyncAt, lastError, needsRepair; from SQLDelight flows), `deviceName`, `maxPeers`, `invite` (`InviteState(profileName, code, expiresAtEpochSec)` or null), `pendingPairing` (from the node), `join` (`Idle | Connecting | WaitingForConfirm(sas, peerName) | Done | Failed(messageKey)`).
Actions: `startInvite(profileId)`, `cancelInvite()`, `confirmPairing()`, `rejectPairing()`, `previewInvite(code)` → profile name or an error (expired/invalid), `join(code, JoinTarget)` (runs `join` then `completeJoin` in `viewModelScope`), `syncNow(peerId?)`, `unshare(peerId, shareId)`, `removePeer(peerId)`, `removeAllPeers()`, `setDeviceName`, `setMaxPeers(1..10)`. Errors become message keys, never raw exception text.

## Part B — screens (`ui/src/commonMain/kotlin/com/yogeshpaliyal/deepr/ui/screens/sync/`)
Use `koinViewModel<SyncViewModel>()` like the other screens, Material3, existing components (`SettingsSection`/`SettingsItem`, `QrCodeDialog` or its QR composable, `rememberQrScanLauncher` which is null where there's no camera, `rememberCopyLinkAction` for copy). Every control has a content description.
1. **`SyncSettingsScreen`** (a `Screen` nav key, reached from a new "Device sync" row in `Settings.kt`): device name (editable), max peers (1–10, default 5), buttons **Share a profile** and **Join a shared profile**, peers list (name, shared profiles, last sync as relative time, last error, "needs re-pair" badge) with per-peer menu **Sync now / Unshare <profile> / Remove device**, and **Remove all devices** with a confirm dialog that says local links are kept.
2. **`ShareProfileScreen`** (nav key with optional `profileId`): pick a profile (preselect the current one), then show the invite as a QR code + the text code with a Copy button + a countdown to expiry (10 min) + Cancel. When `pendingPairing` appears: a dialog "Confirm this code matches on <device>: 123 456" with **Confirm** / **Reject**. Also add **Share this profile…** to `ProfileSelectorMenu`.
3. **`JoinScreen`**: paste field (+ **Scan QR** only if the scanner is non-null), shows the inviter's profile name from `previewInvite`, choose **New profile** (name defaults to the invite's) or **Merge into** (dropdown of existing profiles), **Join** → "Check that <device> shows 123 456" + waiting spinner → done/failed.
Strings: English in `ui/src/commonMain/composeResources/values/strings.xml` (other locales fall back to English). Same-network limitation shown once as a hint on SyncSettingsScreen.
