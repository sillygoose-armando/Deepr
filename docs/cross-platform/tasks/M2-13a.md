# M2-13a — Platform link-actions bridge (prepare Home's move)

GitHub issue: #7 (first half; M2-13b moves Home/Dashboard2/Splash)

## Goal
`Home.kt` (still in `:app`) does three Android-only things from its item menu: **Share** (ACTION_SEND chooser), **Open with** (`openDeeplinkExternal`) and **home-screen shortcuts** (`ShortcutMenuItem` + `CreateShortcutDialog`). Put them behind a small bridge **now**, while Home is still in `:app`, so CI proves Android parity before M2-13b moves Home to `:ui`. Also move the shared-text/clipboard composition locals and `ShowQRCodeMenuItem` to `:ui`. **No user-visible change on Android.**

## Part A — the bridge (`:ui` commonMain, package `com.yogeshpaliyal.deepr.ui.platform`, file `PlatformLinkActions.kt`)
```kotlin
class PlatformLinkActions(
    val share: ((text: String) -> Unit)? = null,
    val openExternal: ((link: String) -> Boolean)? = null,
    val shortcutMenuItem: (@Composable (account: GetLinksAndTags, onClick: (GetLinksAndTags) -> Unit) -> Unit)? = null,
    val shortcutDialog: (@Composable (account: GetLinksAndTags, onDismiss: () -> Unit) -> Unit)? = null,
)
val LocalPlatformLinkActions = staticCompositionLocalOf { PlatformLinkActions() }
```
(public: `:app` provides it). `null` means "not available on this platform": the caller hides that menu item or dialog.

## Part B — Android provider (`:app`)
In `MainActivity.kt`, add to the existing `CompositionLocalProvider(...)`:
`LocalPlatformLinkActions provides remember(context) { PlatformLinkActions(share = { text -> <today's ACTION_SEND code from Home.kt ~684-692, verbatim, using context> }, openExternal = { link -> openDeeplinkExternal(context, link) }, shortcutMenuItem = { account, onClick -> ShortcutMenuItem(account, onClick) }, shortcutDialog = { account, onDismiss -> CreateShortcutDialog(<same args as Home.kt ~591-595>) }) }` (`context = LocalContext.current` in that composable scope; check the exact `CreateShortcutDialog` parameters in Home.kt and reproduce them). `ShortcutMenuItem.kt`, `CreateShortcutDialog.kt`, `ShortcutUtils.kt` and `openDeeplinkExternal` stay in `:app` untouched.

## Part C — Home.kt uses the bridge (still in `:app`)
`val linkActions = LocalPlatformLinkActions.current` at composable scope, then:
- `is Share ->`: keep the analytics call; then `linkActions.share?.invoke(formatShareText(it.item))` (formatShareText unchanged). Render the Share menu item only `if (linkActions.share != null)`.
- `is MenuItem.OpenWith ->`: `linkActions.openExternal?.invoke(it.item.link)`. Render the "Open with" menu item only if non-null.
- The `ShortcutMenuItem(account, {...})` menu entry (~809) → `linkActions.shortcutMenuItem?.invoke(account) { onItemClick(Shortcut(it)) }`.
- `showShortcutDialog?.let { deepr -> CreateShortcutDialog(...) }` (~590) → `showShortcutDialog?.let { deepr -> linkActions.shortcutDialog?.invoke(deepr) { showShortcutDialog = null } }`.
- Remove the then-unused imports (Intent, openDeeplinkExternal, CreateShortcutDialog, ShortcutMenuItem if unused), because ktlint fails on unused imports.
Everything else in Home stays as is (Copy, toasts, BackHandler, etc. are handled when it moves in M2-13b).

## Part D — moves to `:ui` (same packages)
- `data class SharedLink`, `val LocalSharedText`, `val LocalClipboardLink` (declared in `MainActivity.kt` ~75 and ~221–224, package `com.yogeshpaliyal.deepr`) → `ui/src/commonMain/kotlin/com/yogeshpaliyal/deepr/SharedContent.kt` (same package; `ClipboardLink` is already in `:ui`). Remove them from MainActivity.kt.
- `ui/screens/home/ShowQRCodeMenuItem.kt` (`:app`) → `:ui` commonMain, same package, `R.string` → `Res.string`.
