# M2-09 — Navigation on multiplatform Navigation3

GitHub issue: #3 · DECISIONS: D6 (JetBrains port), D10 (Kotlin ≤ 2.3 deps)

## Goal
1. Switch the app from androidx Navigation3 **alpha** (`navigation3-ui 1.0.0-alpha09`, Android-only UI) to the multiplatform stack: `org.jetbrains.androidx.navigation3:navigation3-ui:1.1.2` (it pulls `androidx.navigation3:navigation3-runtime:1.1.7`) and `org.jetbrains.androidx.lifecycle:lifecycle-viewmodel-navigation3:2.10.0`. All checked: Kotlin stdlib 2.2.20, CMP 1.10.
2. Move the navigation **types** into `:ui` `commonMain` so shared screens can navigate.
Navigation behaviour on Android is unchanged: same back stack semantics, same per-entry ViewModel scoping, same saved state.

## Part A — versions (`gradle/libs.versions.toml`, `app/build.gradle.kts`, `ui/build.gradle.kts`)
- `nav3Core` → remove the androidx alpha entries. New entries: `jetbrains-navigation3-ui = { module = "org.jetbrains.androidx.navigation3:navigation3-ui", version = "1.1.2" }`, `androidx-navigation3-runtime = { module = "androidx.navigation3:navigation3-runtime", version = "1.1.7" }`, `jetbrains-lifecycle-viewmodel-navigation3 = { module = "org.jetbrains.androidx.lifecycle:lifecycle-viewmodel-navigation3", version = "2.10.0" }`.
- `lifecycleRuntimeKtx` `2.9.3` → `2.10.0`. The nav3 artifacts require lifecycle 2.10; keep all androidx.lifecycle artifacts aligned.
- `:ui` commonMain: `api(libs.jetbrains.navigation3.ui)`, `api(libs.androidx.navigation3.runtime)`, `api(libs.jetbrains.lifecycle.viewmodel.navigation3)`.
- `app/build.gradle.kts`: replace the three old navigation3 dependencies with the new aliases (or drop them, since `:app` gets them via `:ui`'s `api`; your choice, but no leftovers of the alpha aliases).

## Part B — move the types (package `com.yogeshpaliyal.deepr.ui`)
From `app/src/main/java/com/yogeshpaliyal/deepr/ui/Navigation.kt` to `ui/src/commonMain/kotlin/com/yogeshpaliyal/deepr/ui/Navigation.kt`: `LocalNavigator`, `sealed interface BaseScreen : NavKey`, `interface Screen`, `interface TopLevelRoute` (keep `val label: Int` as is; it changes when those screens move), `class TopLevelBackStack` (verbatim).
- `LocalNavigator`'s default currently constructs `TopLevelBackStack(Dashboard2())`, and `Dashboard2` is still in `:app`. Change the default to `compositionLocalOf<TopLevelBackStack<BaseScreen>> { error("LocalNavigator not provided") }`. MainActivity always provides it (`CompositionLocalProvider(LocalNavigator provides backStack)` at MainActivity.kt:269). Confirm with `codegraph callers LocalNavigator` that every reader is under that provider, and log the result.
- `data class AddLinkScreen(...) : Screen` **stays** in `:app` (keep the file `app/.../ui/Navigation.kt` with just that class). Implementing `Screen` from another module is fine; only the direct subtypes of the sealed `BaseScreen` must share its module.

## Part C — MainActivity NavDisplay (lines ~303–333)
Migrate to the 1.1 API with the same behaviour:
- `rememberSceneSetupNavEntryDecorator()` and `rememberSavedStateNavEntryDecorator()` were replaced in 1.0/1.1 (saved state is `rememberSaveableStateHolderNavEntryDecorator()`; scene setup is built in). Keep `rememberViewModelStoreNavEntryDecorator()`.
- Keep `backStack = backStack.backStack`, `onBack = { backStack.removeLast() }`, and the `entryProvider` lambda logic (TopLevelRoute vs Screen) unchanged, adapting only the API shape (e.g. `NavEntry(key) { … }`).
- **Read the actual 1.1.x API** from the downloaded jars/sources under `~/.gradle` (allowed) before editing. In the Worker log, write the old and new `NavDisplay(...)` call side by side, and the source file where you confirmed each decorator name.
