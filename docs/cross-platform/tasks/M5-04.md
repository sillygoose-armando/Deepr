# M5-04 — iOS `P2pCrypto` (CryptoKit via cryptography-kotlin) + crypto test vectors on every platform

GitHub issue: #12. Contract: `shared/src/commonMain/kotlin/com/yogeshpaliyal/deepr/p2p/core/P2pCrypto.kt` (read the KDoc: raw 65-byte public keys, 32-byte private scalars, ciphertext‖16-byte tag, 12-byte nonces). Reference implementation: `shared/src/jvmShared/kotlin/com/yogeshpaliyal/deepr/p2p/jvm/JvmP2pCrypto.kt`. Decision: `docs/cross-platform/DECISIONS.md` **D8** (cryptography-kotlin CryptoKit provider; we're on Kotlin 2.3.21 now, so use **0.6.0**, which D8 said needs Kotlin ≥ 2.3.20). **Wire format must be byte-identical to the JVM implementation**: an iPhone pairs with an Android phone.

## Part A — dependency
Catalog: `cryptography-core` and `cryptography-provider-cryptokit` (`dev.whyoleg.cryptography`, version `0.6.0`). Add both to `shared` **iosMain** only. If iOS linking later fails with `swiftCompatibility…` errors, D8 names the fix (the `dev.whyoleg.cryptography` Gradle plugin); don't add it pre-emptively.

## Part B — `shared/src/iosMain/kotlin/com/yogeshpaliyal/deepr/p2p/ios/CryptoKitP2pCrypto.kt`
`class CryptoKitP2pCrypto : P2pCrypto` using `CryptographyProvider.CryptoKit` and the **blocking** APIs (`…Blocking`):
- `randomBytes`: `CryptographyRandom.nextBytes(size)`.
- ECDH P-256: generate with `ECDH.Curve.P256`; export public as `EC.PublicKey.Format.RAW` (65-byte uncompressed) and private as RAW (32-byte scalar) — check the 0.6.0 formats; if private RAW isn't supported, use the format D8 says works and convert. `ecdh(priv, peerPub)`: decode both, `sharedSecretToByteArrayBlocking(peer)`; invalid points must throw.
- HKDF-SHA256 (`HKDF`, digest `SHA256`, salt, info, output length), HMAC-SHA256, AES-256-GCM with **caller-supplied 12-byte IV** and 128-bit tag (the IV-taking functions are `@DelicateCryptographyApi`: opt in, with a one-line comment why: the protocol's envelope supplies its own random nonce). Decrypt failures must throw.

## Part C — vectors that every implementation must pass, `shared/src/commonTest/kotlin/com/yogeshpaliyal/deepr/p2p/core/P2pCryptoVectorsTest.kt`
- `expect fun cryptoUnderTest(): P2pCrypto` in commonTest; actuals: `jvmTest` → `JvmP2pCrypto()`, `iosTest` → `CryptoKitP2pCrypto()`. Add `commonTest.dependencies { implementation(kotlin("test")) }` (jvmTest/iosTest already have it).
- **Published known answers** (hex constants in the test; cite the source in a comment):
  - HKDF-SHA256: RFC 5869 Appendix A.1 (test case 1).
  - HMAC-SHA256: RFC 4231 test case 2 (`"Jefe"` / `"what do ya want for nothing?"`).
  - AES-256-GCM: a NIST/McGrew-Viega 256-bit-key test case **with AAD** (e.g. GCM spec test case 16) → ciphertext‖tag; and decrypt of it; and decrypt with one flipped tag bit throws.
  - ECDH P-256: a NIST CAVP KAS ECC CDH P-256 vector (private scalar + peer public point → shared x) — build the 65-byte public key as `04‖X‖Y`.
- **Protocol vector** (pins the whole chain the way `Pairing.kt` uses it): fixed private keys for A and B ⇒ `ecdh` both ways equal; `hkdfSha256(shared, salt=32×0x01, info="deepr-p2p-v1|A|B", 32)` equals a hex constant you compute with `JvmP2pCrypto` and paste in.
- Behaviour: `generateEcdhKeyPair()` sizes (65/32, public starts with `0x04`); two fresh pairs agree on the secret; `ecdh` with a 65-byte point not on the curve throws; `randomBytes(32)` twice differ.
- Also write the same known-answer values to `docs/p2p-sync/vectors/crypto.json` (the sync track's PLAN asks for vectors there) — one JSON object per case with hex fields.
