# M5-01 — `P2pNode`: the sync protocol service in `:shared` (no network yet)

GitHub issue: #12. Spec: `docs/p2p-sync/PLAN.md` § Protocol (v1) — **read it fully; never change the protocol or merge semantics** (proposals go to PLAN.md "Proposals", then stop).

## Goal
Everything between the existing core (`shared/src/commonMain/kotlin/com/yogeshpaliyal/deepr/p2p/core/`: `PairingInviter`/`PairingJoiner`, `seal`/`open` + `ReplayGuard`, `SyncEngine`, `SyncStore`) and the network, in **pure common Kotlin**, so later tasks only plug in an HTTP server/client (M5-02), secret stores (M5-03), UI (M5-05). Tested end-to-end in-process on the JVM.

## Part A — `shared/src/commonMain/kotlin/com/yogeshpaliyal/deepr/p2p/node/`
1. `SecretStore` interface: `fun seal(plain: ByteArray): ByteArray` / `fun open(sealed: ByteArray): ByteArray?` (null = can't decrypt ⇒ DB was cloned onto another device). Used for `SyncPeer.keyEnc`. Plus `class InMemorySecretStore` (test-only use; XOR-free: store a random 32-byte AES key and use `P2pCrypto.aesGcmEncrypt` with a random nonce prefix).
2. `fun interface HttpPost { suspend fun post(host: String, port: Int, path: String, body: String): HttpReply }` and `data class HttpReply(val status: Int, val body: String)`. Paths are the full `/p2p/v1/...` paths from the spec.
3. `class P2pNode(db: DeeprDB, crypto: P2pCrypto, secrets: SecretStore, http: HttpPost, clock: () -> Long = …ms)`:
   - Identity: `deviceId` from `SyncDevice`; `deviceName` (stored in `SyncDevice.deviceName`; add a `setDeviceName` query only if missing).
   - **Inviter:** `startInvite(profileId: Long, hosts: List<String>, port: Int): String` → shares the profile if needed (`SyncStore.shareProfile`), creates a `PairingInviter` invite, returns `encodeInvite(...)`. `cancelInvite()`. Invite single-use, 10 min (core already enforces).
   - **Server side:** `suspend fun handle(path: String, body: String, remoteHost: String?): HttpReply`:
     - `/p2p/v1/pair`: only while an invite is active; `PairingInviter.accept` → keep the `PairingResult` as *pending* (exposed as `pendingPairing: StateFlow<PendingPairing?>` with peer name + SAS) and reply the `JoinResponse`. Check `maxPeers` (`countPeers`) unless the peer already exists (then just attach the share, spec step 6).
     - `/hello`, `/sync`, `/unshare`, `/unpair`: parse `Envelope`, look up the peer (unknown ⇒ **401, empty body**), `secrets.open(keyEnc)` (null ⇒ 401 and `markAllPeersNeedRepair` — clone detection), `open(...)` with one shared `ReplayGuard`; dispatch: `/sync` → `SyncEngine.handle(peerId, request)` (check the peer is linked to that share, else 403); `/hello` → list of shareIds linked with this peer; `/unshare` → `unlinkPeerShare`; `/unpair` → `deletePeer`. Reply sealed the same way. On success update `updatePeerAddress` from `remoteHost` (keep the port).
     - Bad input/crypto errors ⇒ 400/401 with **no detail**; never leak exception messages.
   - `confirmPairing()` (inviter, after the user compares the SAS): persist the peer (`insertPeer` with `secrets.seal(pairKey)`, host/port unknown ⇒ '' / 0 until its first request) + `linkPeerShare`; `rejectPairing()` drops it.
   - **Joiner:** `suspend fun join(code: String, target: JoinTarget): PendingJoin` with `sealed interface JoinTarget { data class NewProfile(val name: String); data class MergeInto(val profileId: Long) }`: `decodeInvite` (expiry), check `maxPeers`, `PairingJoiner`, POST `/pair` to the invite's hosts in order (first that answers), `finish` ⇒ `PendingJoin(sas, peerName)`. Then `suspend fun completeJoin(pending): Boolean` polls `/hello` (sealed with the pair key; every 2 s, up to 2 min) until the inviter confirmed; on success create/choose the profile, share it under the invite's `shareId` (`insertShare` with that id — the joiner adopts the inviter's shareId), `insertPeer` + `linkPeerShare`, then run a first `syncWith`.
   - **Client:** a private `SyncTransport` that seals `SyncRequest` for the peer (`seal`, path `/p2p/v1/sync`), POSTs to `lastHost:lastPort`, opens the reply. `suspend fun syncPeer(peerId)` = `syncWith` for every share linked to the peer, then `updatePeerSyncStatus(now, "" | short error class name)`. `suspend fun syncAll()`.
   - `suspend fun unshare(peerId, shareId)` / `removePeer(peerId)` / `removeAllPeers()`: best-effort notify the peer (`/unshare`, `/unpair`), then update locally. **Never delete local links.**
   - Serialization: kotlinx.serialization JSON like the core (`Json { ignoreUnknownKeys = true }`).

## Part B — tests `shared/src/jvmTest/kotlin/com/yogeshpaliyal/deepr/p2p/node/P2pNodeTest.kt`
Two nodes A and B, each with an in-memory `JdbcSqliteDriver` (`DeeprDB.Schema.create`, foreign_keys on, as `SilentSaverTest`), `JvmP2pCrypto`, `InMemorySecretStore`, and an in-process `HttpPost` that routes `host == "A"` to `nodeA.handle(...)` (and "B" likewise). Cases:
1. A invites (hosts `["A"]`), B joins `NewProfile("Work")`, both SAS equal, A confirms, `completeJoin` succeeds; a link added on A appears on B after `syncPeer`; a link added on B appears on A.
2. A rejects ⇒ B's `completeJoin` returns false and neither side has a peer.
3. Unknown peer envelope ⇒ 401; replayed envelope ⇒ rejected; tampered body ⇒ 400/401.
4. `removePeer` on B ⇒ A no longer has B; both keep all links.
5. `SecretStore.open` returning null ⇒ 401 and `needsRepair = 1` for all peers.
6. Second invite of another profile to the same peer attaches the share without a new peer row.
