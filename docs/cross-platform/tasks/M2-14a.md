## Goal
`app/src/main/java/com/yogeshpaliyal/deepr/ui/screens/Settings.kt` (513 lines, still in `:app`) has Android-only pieces. Put them behind a bridge **now**, while Settings is still in `:app`, so CI proves Android parity before M2-14b moves it to `:ui`. **No user-visible change on Android**: same rows, same order, same actions.

## Part A — bridge (`:ui` commonMain, package `com.yogeshpaliyal.deepr.ui.platform`, file `SettingsPlatform.kt`, public)
```kotlin
class SettingsPlatform(
    // Rendered where "Data Management" (Backup/Restore) + DriveSettingsItem are today (top of the list).
    val topSections: (@Composable () -> Unit)? = null,
    // Rendered as the first row of "Others" (Local network server) today.
    val localServerRow: (@Composable () -> Unit)? = null,
    val isDeviceSecure: (() -> Boolean)? = null,        // KeyguardManager check for app lock
    val sendFeedback: (() -> Unit)? = null,             // ACTION_SENDTO email chooser
    val requestReview: (() -> Unit)? = null,            // ReviewManager.requestReview(activity)
    val shareApp: ((text: String) -> Unit)? = null,     // ACTION_SEND chooser
    val recreateForLanguage: (() -> Unit)? = null,      // (activity as MainActivity).recreate()
)
val LocalSettingsPlatform = staticCompositionLocalOf { SettingsPlatform() }
```

## Part B — Android provider (`:app`, `MainActivity.kt`, in the existing `CompositionLocalProvider` inside `Dashboard` where `context` exists)

- `topSections`: the whole `SettingsSection("Data Management") { … }` block (Backup → `navigator.add(BackupScreen)`, Restore → `navigator.add(RestoreScreen)`) **followed by** `DriveSettingsItem()`. Inside the lambda use `val navigator = LocalNavigator.current`.
- `localServerRow`: the "Local network server" `SettingsItem(…)` (→ `navigator.add(LocalNetworkServer)`).
- `isDeviceSecure`: the KeyguardManager logic Settings uses today (read lines ~121 and ~340–370 to see exactly what's checked; reproduce it).

- `shareApp`: the share-app Intent block (~423–440); Settings passes the text.

Strings used by moved rows keep using `R.string` (they're in `:app`).

## Part C — Settings.kt uses the bridge (still in `:app`)
`val settingsPlatform = LocalSettingsPlatform.current`, then:
- Replace the Data Management section + `DriveSettingsItem()` with `settingsPlatform.topSections?.invoke()`.
- Replace the Local network server row with `settingsPlatform.localServerRow?.invoke()`.
- App-lock toggle: where `keyguardManager` was used, use `settingsPlatform.isDeviceSecure?.invoke() == true`, keeping the same branches and toasts. Hide the Security section if `isDeviceSecure == null`.
- Feedback / Rate / Share-app rows: call the bridge members; hide each row when its member is null.
- Language dialog `onLanguageSelect`: replace `(context as? MainActivity)?.recreate()` with `settingsPlatform.recreateForLanguage?.invoke()`.
- `ServerStatusBar(...)` (~156): keep as is for now (M2-14b reuses `LocalHomeServerBarBuilder`).
- Remove now-unused imports (ktlint fails on them).

## Part D — LanguageUtil data → `:shared`
`app/.../util/LanguageUtil.kt`: move the pure parts (constants, `data class Language`, `availableLanguages`, `getLanguageDisplayName`, `getLanguageNativeName`) to `shared/src/commonMain/kotlin/com/yogeshpaliyal/deepr/util/LanguageUtil.kt` as `object LanguageUtil`. The Android-only `updateLocale(context, …)` goes to `shared/src/androidMain/.../util/LanguageLocale.android.kt` as an extension `fun LanguageUtil.updateLocale(context: Context, …)` with the same signature. Callers of `LanguageUtil.updateLocale(...)` keep compiling via the same name (check with `codegraph callers updateLocale`; if a call site needs an import of the extension, add it). Log the callers.
