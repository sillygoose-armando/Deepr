# M4-02 — `iosApp/` Xcode project via XcodeGen + CI simulator build (unsigned)

GitHub issue: #11

## Goal
A minimal iOS app that hosts the shared UI from M4-01 (`ui/src/iosMain/kotlin/com/yogeshpaliyal/deepr/ui/MainViewController.kt`: `initKoin(dataDir)`, `MainViewController()`; framework `DeeprUI`, static). The project is **generated** by XcodeGen from `iosApp/project.yml`; the `.xcodeproj` is not committed. No Mac here: nothing in this task can be compiled locally; write carefully, CI verifies. Do not change any Kotlin code.

## Part B — CI (`.github/workflows/kmp-ios.yml`, same job, after the Gradle compile step)
```yaml
      - name: Generate Xcode project
        run: brew install xcodegen && cd iosApp && xcodegen generate
      - name: Build iOS app for the simulator (unsigned)
        run: >
          xcodebuild -project iosApp/Deepr.xcodeproj -scheme Deepr -configuration Debug
          -sdk iphonesimulator -destination 'generic/platform=iOS Simulator'
          ARCHS=arm64 ONLY_ACTIVE_ARCH=NO CODE_SIGNING_ALLOWED=NO build
```
The runner is `macos-15-intel`: `ARCHS=arm64` cross-builds the arm64 simulator slice (matches our only simulator target, `iosSimulatorArm64`); nothing runs the simulator in this task (M4-04).
Also add `iosApp/**` to the workflow's `paths` trigger if it has one.
