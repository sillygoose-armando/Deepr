## Goal

Replace it in `QRCodeDialog` with **`io.github.alexzhirkevich:qrose:1.3.1`** (Compose Multiplatform QR; publishes android, desktop, iosArm64 and iosSimulatorArm64; checked on Maven Central) and move the dialog to `ui/src/commonMain`, same package `com.yogeshpaliyal.deepr.ui.components`. ### ❗ Blocker / open question (rule 1 — recorded, not done): qrose 1.3.1 needs Kotlin ≥ 2.4
`./gradlew :ui:compileKotlinJvm ...` **fails** with the briefed 1.3.1:
- qrose 1.3.1's POM declares `kotlin-stdlib 2.4.0`, and its classes carry Kotlin metadata `mv=[2,4,0]` (verified via `javap`).
- This project compiles with Kotlin `2.2.20` (`gradle/libs.versions.toml:7`, compiler reads metadata ≤ 2.3.0), so **any** qrose 1.3.1 class fails to load: `Class 'kotlin.Unit' was compiled with an incompatible version of Kotlin. The actual metadata version is 2.4.0, but the compiler version 2.2.0 can read versions up to 2.3.0.` Same would happen on Android and iOS in CI.
- **Verified with a temporary experiment:** with `qrose` pinned to **1.1.2** (stdlib 2.3.0, same API surface: `QrPixelShape.circle()`, `QrBrush.solid()`, same DSL — checked by diffing sources of both versions), the full acceptance command **passes**. I then restored 1.3.1 exactly as briefed; the repo is currently left in the brief-compliant but non-compiling state.
- **Orchestrator decision needed** (both are outside my scope):
  1. pin `qrose = "1.1.2"` (instance-verified green with my code — smallest change), or
  2. upgrade the project to Kotlin ≥ 2.4 (big change: COMPOSE/kotlin-stdlib/gradle-depends ripple across all modules).
