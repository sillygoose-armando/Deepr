# M3-03 — Desktop UI smoke test

GitHub issue: #10

## Goal
A Compose UI test on the desktop JVM that renders the **real** common UI (`DeeprTheme { DeeprApp(...) }`) against a real in-memory database. It proves the multiplatform UI actually works end to end, not just that it compiles. It runs in CI on every push.

## Test (`desktopApp/src/test/kotlin/com/yogeshpaliyal/deepr/desktop/DeeprAppUiTest.kt`)
- Dependencies (`desktopApp/build.gradle.kts`): `testImplementation(compose.desktop.uiTestJUnit4)` (Compose Multiplatform accessor; or the explicit `org.jetbrains.compose.ui:ui-test-junit4` at the CMP version), `testImplementation(compose.desktop.currentOs)` if needed for the native runtime, `testImplementation(libs.junit)` (JUnit4; the compose rule is JUnit4).
- Koin: before each test, start Koin with `sharedModule` + `desktopModule(tempDir)`, or an equivalent test module using an in-memory `JdbcSqliteDriver(JdbcSqliteDriver.IN_MEMORY, Properties().apply { put("foreign_keys","true") }, DeeprDB.Schema)`; stop it after.
- With `createComposeRule()`: `setContent { DeeprTheme { DeeprApp(sharedText = null, resetSharedText = {}, clipboardLink = null, resetClipboardLink = {}) } }`, then:
  1. the bottom navigation is shown: the three top-level labels are displayed (look the texts up from the English `strings.xml` keys used as `TopLevelRoute.label`: `home`, `tags`, `settings`; find nodes by text);
  2. clicking the Settings tab shows a known Settings row text (e.g. the "Theme" row, from `Res.string.theme`'s English value);
  3. clicking back to Home doesn't crash.
  Use `waitForIdle()`/`waitUntil` where needed. Keep it robust: text lookups, not pixel checks.
- If skiko can't load on this aarch64 machine, mark the test with a JUnit `Assume` on a skiko-availability check and say so in the Worker log. **It must run in CI (ubuntu x64)**; the orchestrator verifies it there.
